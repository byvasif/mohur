Möhür

Certificate generation system
möhür — Azerbaijani for “seal, stamp”: the mark that makes a document official.
DATE .......... 15.09.2026
STATUS ........ IN PRODUCTION
PLATFORM ...... Google Workspace
RUNTIME ....... Apps Script
FIRST DOC ..... F3B5DR5

You write one row in a spreadsheet. The system turns that row into a certificate that is numbered, carries a QR code, exists as a PDF and is filed. Nobody touches it in between.

§ 01

The problem it solves

Organisations that inspect, test, calibrate or train issue a document at the end of every job. That document needs a unique number, the number must never appear on a second document, the file has to survive as a PDF, and somebody has to be able to find it years later.

In most places this is done by hand: copy the template, fill the fields, look up the next number in a register, export to PDF, move the file into a folder. Every step depends on a person. Duplicate numbers, empty fields and wrong dates are therefore not the exception but the normal outcome — and they usually surface at the worst possible moment, when an auditor is reading the document.

Möhür reduces that entire chain to changing one cell.

§ 04

What comes out

One row yields four files and the folder that holds them. The folder name is built from the code and the equipment, so whoever searches the archive knows what they are looking at without opening anything.

Why a short version exists

The full certificate runs to four pages with its annexes, but a client, an insurer or a site entrance usually needs only the first two. The system produces both in the same pass, so the two documents can never disagree about the data.

What the QR carries

The QR on page one carries the text below. Anyone scanning it sees which machine was tested, for which company and when, without opening the document. The format is deliberately machine-readable and the field names are in English: the certificate is issued in two languages, but whoever scans the code should not need to know either of them.

EQUIPMENT=Qüllə kran KB-403 COMPANY=Xəzər Tikinti MMC TEST_DATE=14.09.2026 REF=F3B5DR5

The square is a working QR code — scan it. It belongs to certificate F3B5DR5, produced by the live system.

§ 05

Four rules

What makes a document system usable is not its speed but its refusal to produce a wrong document. These four rules hold under every condition.

A number is never reused

Every issued code is written to a separate log. Each new code is checked against that log; if a collision cannot be resolved the system stops and reports it rather than issuing the same number twice.

No half-finished document

If anything fails mid-run, every file created up to that point is removed. A partially filled official document is worse than no document at all.

The template is never touched

The system always works on a copy. After hundreds of certificates the original template is byte-for-byte what it was on day one.

No QR, no certificate

If the code cannot be fetched, nothing is produced. A certificate without its QR looks verifiable while being impossible to verify — the most dangerous of the failure modes.

§ 06

What you configure, what needs code

The shape of the system is not buried in the source. Templates, placeholders and languages live in their own sheet tabs — that is the part you can change without calling a developer.

Done from the sheet

  • Add a template
  • Add a language
  • Move a field around the template
  • Change the result wording — PASS=CONFORMS
  • Set the page the short version is cut at

Needs code

  • Add a genuinely new data field (“Pressure”, say)
  • Change how files and folders are named
  • Change which fields the QR carries

The system refuses an invented column; a field has to be declared first. That is deliberate — it stops a typo from producing a certificate with a blank on it.

How the second language is set up sums the design up: the English certificate needs one row in the sheet — PASS=CONFORMS;FAIL=DOES NOT CONFORM. Every other field is inherited from the base language. A third language is a handful of rows, not a code change.

§ 07

Adapting it to other fields

The system was built for crane inspection, but what it does is not specific to that trade: a number that never repeats, a scannable QR, a PDF, and an orderly archive. Any document that needs those four runs on the same core; only the column names and the template change.

§ 08

Technical limits

What follows are not shortcomings but facts about the platform. Knowing them before a build is better than discovering them during one.

Google Docs has no page model

The API sees a document as one flat stream; pagination is decided when the document is rendered. “The first two pages” is therefore only well defined if the template contains an explicit page break. If it relies on automatic pagination, the cut point moves as the content grows. On any build that wants a short version, this is the first question to settle.

The QR comes from outside

Apps Script has no QR generator, so the image must be fetched from a third-party service. That makes the script dependent on someone else at runtime. Rather than hide that, the system turns it into a rule: if the service does not answer, no certificate is produced.

Date cells are not text

A date typed into the sheet looks like 14.09.2026 but is stored as a date object, and reading it directly returns something else entirely. The system converts it explicitly. A small detail — and the one most likely to produce a quietly wrong document.
